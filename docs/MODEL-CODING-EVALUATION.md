# 致远一号编程实测与 Hades 接入原则

2026-09-30，Zeus 实测。调用用户已配置的学校接口，未向模型提供个人任务、专注历史、校园凭据或代码仓库。候选函数在没有 Node 权限、禁用网络的隔离 Worker 中执行，限时 4 秒；没有安装进 Hades。密钥没有写入报告。

## 实际测试

“致远一号”是接口服务名称。本次可用的默认调用名为 `deepseek-chat`，不能把结果推广到服务上的所有模型。

| 合成任务 | 直接要求编程 | 结构化要求＋一个公开样例 | 每次验收用例 |
| --- | --- | --- | --- |
| 合并消息并保留删除状态 | 通过 | 通过 | 3 |
| 按活动日筛选，排除仅当天发表的文章 | 通过 | 通过 | 3 |
| 专注区间取并集后扣除暂停时间 | 通过 | 通过 | 5 |
| 当前课程过滤、重复 ID、旧学年与归档状态 | 失败 | 失败 | 5 |

初次 8 次调用通过 6 次。这是四道小题的结果，不是通用能力排名。要求“不修改输入”也纳入验收。初次调用约 4.7～25.2 秒，返回的接口总 token 数约 297～826。

课程题的失败输入含 `archived: "false"`。字符串是 truthy，应该排除该课程；生成代码却用了 `row.archived === true`，错误保留了它。仅报告失败检查序号的修复未通过；重新生成时给出准确反例，及随后一次修复，仍未通过。最后给出原函数并限定把该行改为 `Boolean(row.archived)`，约 7.1 秒后通过原有全部 5 项检查。这证明其能执行明确的小修改，不能证明其能独立定位问题。

`qwen3coder` 和 `glm-5` 的试调用返回 HTTP 403，没有得到可评估代码。权限或接口可用性与模型智力不能混为一谈；本次不对这两个模型评分。

## 可接受的工作方式

1. 首选已验证模板和结构化参数：一句话添加倒计时、打卡清单或已有组件，由 Hades 校验日期、类型和账号权限后保存。模型无需生成可执行代码。
2. 新代码每次只承担一个小函数或一个明确改动，提供输入输出、字段类型、删除与权限规则；避免同时要求界面、网络、数据库和发布。
3. 验收由独立测试决定。覆盖空值、重复数据、删除状态、日期边界、类型异常和输入不被修改，不能采信模型“已通过”的自述。
4. 失败反馈包含准确输入、预期输出与实际差异。仍失败时缩小改动，必要时由开发者定位并给出最小补丁；限制修复次数，不无限重试。
5. 候选在隔离环境测试；不赋予密钥、用户目录、网络和系统命令权限。通过后再进行模块集成、回归与人工检查；模型不能绕过验收自行安装。

目前 Hades 的一句话组件功能采用第一条：支持现有组件、倒计时和打卡清单，不支持聊天直接生成并执行任意插件。这是已经实现的范围。更通用的自动编程、自动发布和任意插件沙箱仍需单独开发与验收。

## 最小改动提示示例

```text
只修改所附函数中导致这个反例失败的部分，保留其余行为。
输入：[{id:"x",year:2026,archived:"false",timetableDates:["2026-09-30"]}]
当前年份：2026；当天：2026-09-30
预期输出：[]
错误：把非空字符串 "false" 当作布尔 false。
将 const archived = row.archived === true;
改为 const archived = Boolean(row.archived);
返回 JSON {"code":"完整函数"}，不调用外部库，不读写文件。
```

复测其他任务仍需新增验收用例，不能把这次给出答案后的成功视为普遍可靠性保证。
