# Hades V3.2 隐私与威胁模型

## 保护对象

- 账号会话、任务、日程、课表摘要、专注记录和界面偏好。
- 只留在设备上的学校登录会话、模型 API 密钥、云厂商凭据和微信提醒配置。
- 同步服务中的账号隔离、历史快照和验证码流程。

## 架构边界

安卓端与电脑端通过同一个 Hades 账号和 HTTPS 同步服务连接。手机不监听局域网端口，不读取电脑文件，也不把学校登录会话或模型 API 密钥加入同步文档。客户端只接受固定 HTTPS 根地址，禁止明文流量和网络跳转。

桌面端继续使用隔离渲染器、窄 IPC 白名单和账号门禁。安卓端使用 Android KeyStore 生成不可导出的 AES-GCM 密钥，对会话令牌和离线缓存加密；系统备份和设备迁移备份均排除应用私有数据。退出账号后个人页面立即锁定。

云同步采用用户会话推导身份，不接受客户端传入用户 ID。写入携带远端版本号；版本冲突返回给客户端，由使用者明确选择云端或手机端数据。服务端限制请求体、请求频率、历史数量和响应缓存，并返回拒绝嵌入、嗅探和来源泄露的安全响应头。

## 已模拟的攻击

`npm run test:security` 只在临时数据库和合成账号上运行，不访问生产服务器，不发送真实邮件。脚本覆盖：

1. 缺失或伪造 Origin 的认证与同步请求；
2. 未登录访问、跨账号读取和伪造用户 ID；
3. 畸形 JSON、原型字段、SQL 注入样式文本和旧版本重放；
4. 错误响应中的令牌及内部细节泄露；
5. 安卓明文网络、系统备份、KeyStore 加密和日志静态检查；
6. 受版本控制源码中的高置信度 API 私钥扫描。

测试结果会写入 `test-results/security-redteam-v3.2.json`，该目录不进入 Git。

## 仍需持续处理的风险

- 未解锁设备上的屏幕内容可能被旁观；后续可增加可选的系统生物识别锁。
- 当前账号服务仍使用既有公网 HTTPS 地址。域名接入需要完成 ICP 备案、证书切换和真实客户端回归后再启用。
- 手机丢失后应在另一设备修改密码以撤销旧会话，并使用系统的远程锁定或抹除能力。
- 本地攻防验证不能替代独立第三方渗透测试、移动应用签名保护和持续依赖漏洞扫描。
